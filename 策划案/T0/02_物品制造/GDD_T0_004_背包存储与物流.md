# GDD_T0_004：二维背包、存储与容器搜索

版本：v0.4
状态：背包、制作入口与左右手快捷位已更新

## 1. 设计目标

背包是T0“行”的核心成长系统，也是探索取舍的主要来源。新方案采用紧密二维网格和变尺寸物品，让物品形状、排列方式与剩余空间共同影响携带能力。

界面参考战术搜刮游戏的信息密度与操作节奏，但使用原创布局、图标、字体和废土工业视觉，不复制具体游戏的品牌素材。

核心体验：

- 玩家一眼看出背包还有多少连续空间。
- 大型工具和材料比小型补给更难携带。
- 整理背包能够真实改善空间利用率。
- 打开背包与搜索容器使用一致的空间记忆。
- 背包升级明显扩大一次远征的有效收获。

## 2. 已确认的界面状态

### 2.1 Tab：默认背包与展开制作

玩家按`Tab`打开个人界面：

```text
┌────────────────────┐
│ 玩家背包      [制作] │
│ 二维物品网格         │
│                    │
├────────────────────┤
│ 饥饿 / 口渴                               │
│          6位快捷栏（1/2为手位）             │
└────────────────────┘
```

- 按`Tab`后默认只显示玩家背包，不自动打开制作窗口。
- 背包窗口右上角固定显示`制作`按钮。
- 点击`制作`后，在背包右侧展开随身制作窗口；背包位置不移动。
- 再次点击`收起制作`、按关闭按钮或退出个人界面时，制作窗口关闭。
- 不显示容器和搜索进度。
- 制作窗口展开后，与背包之间使用明确分隔线。
- 背包位置不因打开其他界面而改变。

### 2.2 搜刮：背包与容器

玩家打开世界容器后：

```text
┌────────────────────┬────────────────────┐
│ 玩家背包            │ 当前容器            │
│ 二维物品网格         │ 未知、已揭示和空格   │
│                    │ 搜索进度             │
├────────────────────┴────────────────────┤
│ 饥饿 / 口渴                               │
│          6位快捷栏（1/2为手位）             │
└─────────────────────────────────────────┘
```

- 左侧仍然是玩家背包，位置和Tab界面保持一致。
- 进入搜刮状态时关闭已展开的制作窗口，右侧显示当前容器。
- 首个通用容器原型采用`4×5`正方形网格，用于验证搜索揭示、跨容器拖放和快速转移；正式容器尺寸由容器数据配置。
- 容器标题、搜索进度和内容状态只出现在右侧。
- 不允许出现“Tab时背包在左，搜刮时背包跑到右侧”的位置交换。

固定左侧背包的目的，是让玩家形成稳定空间记忆，并减少频繁搜刮时的视线跳转。

## 3. 世界与输入状态

- 打开背包、制作或容器界面时世界不暂停。
- 玩家不能移动、冲刺、跳跃、旋转视角、进行世界交互或使用工具。
- 鼠标解除锁定并用于UI操作。
- 饥饿、口渴、机器、环境和其他世界对象继续更新。
- `Tab`打开或关闭个人界面。
- 容器界面通过世界交互打开，`Tab`或`Esc`关闭。
- 玩家被强制移动出交互距离时，容器界面自动关闭。
- UI采用大面积半透明遮罩，但画面边缘仍能看到世界变化。

## 4. 二维空间模型

### 4.1 基础格

- 背包由正方形基础格组成。
- 基础格是空间计算单位，不是物品卡片。
- 每个基础格必须保持正方形；相邻格无空隙拼接，只保留一条共享边界线。
- 物品卡覆盖自身占用的全部连续格，只绘制一个完整外框。
- 1×2物品不能表现成上下两张卡片。
- 非法重叠、超出边界或空间不连续时禁止放置。

### 4.2 背包等级

| 背包等级 | 网格 | 总格数 | 定位 |
|---|---:|---:|---|
| 一级背包 | 3×4 | 12 | 开局短距离探索 |
| 二级背包 | 4×5 | 20 | 城区中距离搜集 |
| 三级背包 | 5×6 | 30 | T0后期工业材料远征 |

- 升级替换当前背包空间，不叠加多个背包容量。
- 旧背包作为升级配方的输入材料被消耗，不作为独立容器保留。
- 背包升级不能覆盖已有物品。
- 更换为更小背包时，如果现有物品无法容纳，则禁止更换并显示具体原因。
- 背包形状和总格数由数据配置，不在程序中写死。
- T0背包内部没有损坏格、锁定格或不可用区域；网格中的每个格位都可正常使用。

## 5. 物品尺寸

每种物品定义：

- `gridWidth`：横向占格。
- `gridHeight`：纵向占格。
- `canRotate`：是否允许旋转90度。
- `stackLimit`：同一物品卡可容纳的数量。
- `inventoryIcon`：背包图标。
- `iconPadding`：图标在占用区域内的安全边距。

第一批暂定尺寸：

| 物品 | 默认尺寸 | 可旋转 | 堆叠 | 说明 |
|---|---:|---|---|---|
| 一袋面包 | 1×1 | 否 | 否 | 小型生存补给 |
| 一瓶饮用水 | 1×1 | 否 | 否 | 开局安全饮品 |
| 石头 | 1×1 | 否 | 否 | 小型基础材料 |
| 铁棍 | 1×1 | 否 | 否 | 基础金属材料，尺寸为开发抽象 |
| 铁板 | 1×1 | 否 | 否 | 基础金属材料，尺寸为开发抽象 |
| 木材 | 1×1 | 否 | 否 | 基础建造材料，尺寸为开发抽象 |
| 铁锤 | 1×2 | 是 | 否 | 单件耐久工具 |
| 简易撬棍 | 1×3 | 是 | 否 | 单件耐久工具 |

除铁锤和简易撬棍外，当前物品统一为1×1，优先降低T0程序、美术和关卡验证成本。正方形物品无需旋转；所有非正方形物品允许旋转90度。

### 5.1 铁锤表现标准

- 铁锤完整占用连续1×2区域。
- 只绘制一圈覆盖整个1×2区域的物品外框。
- 锤头和握柄属于同一张物品图标。
- 图标约占卡片内部80%—85%，不能因过大内边距显得物品很小。
- 选中时整张1×2卡片使用同一高亮。
- 调试版本可以显示小型`1×2`尺寸标记，正式版本默认隐藏。

## 6. 非堆叠物品实例

- T0当前所有物品都不能堆叠，每个单位分别占用一张物品卡。
- 同种材料获得多个时，需要分别占用对应空间。
- 工具、材料、食物和饮品均遵守同一规则。
- 数量字段只用于配方和转移操作汇总，不代表一格中存放多个单位。
- 每个物品实例具有稳定ID；耐久、快捷栏绑定、容器位置和搜索状态都引用该实例。
- 后续如果重新启用堆叠，必须作为独立版本升级处理，不预设当前UI已经支持。

## 7. 背包操作

### 7.1 基础操作

- 左键拖动：拿起并移动物品。
- 左键释放：放置到合法位置。
- `R`：旋转当前允许旋转的物品。
- 双击：在当前两个容器之间快速转移。
- `Shift＋左键`：快速转移整件或整栈物品。
- 右键：打开物品操作菜单；使用、装备、绑定快捷栏或丢弃。
- 悬停：显示名称、尺寸、数量、用途、耐久和效果。

具体按键必须通过Input System配置，不直接写死在UI逻辑中。

### 7.2 放置反馈

| 状态 | 反馈 |
|---|---|
| 可放置 | 目标格使用绿色半透明预览 |
| 与物品重叠 | 冲突格和物品外框使用红色 |
| 超出边界 | 越界部分显示红色并禁止放置 |
| 不可旋转 | 给出轻量错误反馈，不改变物品方向 |

- 颜色不能作为唯一提示，必须结合边框形态或图标。
- 关闭界面时，鼠标正在持有的物品必须返回来源位置；不得掉落或销毁。
- 如果来源位置已经失效，则尝试自动放入背包；仍无法放入时阻止关闭并要求处理。

### 7.3 自动放置

快速拾取或转移时按以下顺序处理：

1. 按从左上到右下的固定扫描顺序寻找第一个合法连续空间。
2. 如果默认方向无法放置且物品不是正方形，自动尝试旋转方向。
3. 两种方向均失败时拒绝转移，并显示“背包没有连续空间”。

“总空格数足够”不代表一定能放入；系统必须检查连续形状。

## 8. 6位快捷栏与左右手位

- 快捷栏固定显示在屏幕底部中央。
- 饥饿和口渴条位于快捷栏上方。
- T0初始提供6个快捷栏位置，并预留后续扩展。
- 数字键`1`至`6`选择，鼠标滚轮循环切换。
- `1`号与`2`号位置分别模拟左手和右手，是实际持有位，不占用背包网格。
- 每个手位T0只能持有一件物品；物品转入手位后从背包网格移除，放回背包时必须重新通过连续空间校验。
- `3`至`6`号位置仍是背包物品的快捷引用，不提供额外储存空间；被绑定物品继续占用背包网格。
- 左右手位与普通快捷引用必须在视觉上分组，避免玩家误认为六个位置都能额外储物。
- T0物品默认按单手物品处理；双手物品、禁止手持标签和手位占用数量预留数据字段，暂不启用具体内容。
- 移动物品不会自动解除绑定；物品实例仍存在时绑定继续有效。
- 同一物品实例不能同时绑定多个快捷栏位置。
- 消耗品耗尽后不会自动寻找并绑定背包中的同类物品。
- 工具损坏后解除快捷栏绑定，不在快捷栏中保留损坏状态。
- 物品被消耗、丢弃、损坏或不存在时，对应快捷栏变为空。
- 材料允许绑定快捷栏，便于后续建造或特殊交互。
- 选中工具时显示其耐久；选中消耗品时显示数量。

## 9. 随身制作界面

玩家按`Tab`时不自动显示制作内容。点击背包右上角`制作`按钮后，界面从左到右排列为“玩家背包—配方图标网格—配方详情”：

- 中部使用图标网格显示已解锁配方。
- 右部显示选中配方详情。
- 显示输入、当前持有数量、输出、缺失条件和制作按钮。
- 制作材料统计玩家背包网格、左手位和右手位中的全部物品，也包括已绑定`3`至`6`号快捷引用的背包物品。
- `3`至`6`号快捷栏只是引用，因此不得重复计算材料；左右手位中的物品是独立持有位置，需要正常计入一次。
- 制作完成后优先将产物放回由材料释放出的空间，再执行自动放置。
- 产物没有合法连续空间时禁止开始制作。
- 支持单次、连续和批量制作，并以制作队列顺序执行。
- T0制作队列最多同时排入3项。
- 开始每个制作项前校验并锁定该项材料。
- 计算产物空间时先模拟移除本次材料，因此允许产物使用材料释放出的格位。
- 队列确认时一次性校验并预留全部队列产物所需空间，不只预留当前制作项。
- 全部预留格位显示半透明产物占位，整理背包时不能放入其他物品。
- 玩家可以在制作期间关闭界面；制作继续进行。
- 关闭界面后，游戏右上角显示当前产物、队列数量和制作进度。
- 玩家制作期间仍可移动，但移动速度降低；具体倍率等待程序测试。
- 制作减速与饥饿、口渴档位减速不相乘，最终采用各来源中最低的速度倍率，并继续遵守最低非零移动速度。
- 制作完成后产物进入预留位置；不得因玩家关闭界面而掉落或消失。
- 第一阶段取得铁棍后显示简易撬棍配方，并提示仍缺少石头。

## 10. 容器搜索

### 10.1 内容生成

- 容器内容在容器生成或存档创建时确定，不能在每次打开时重新抽取。
- 固定关键物品和随机战利品分别配置。
- 开局木制储物柜固定包含铁棍，不允许随机内容替换或挤出。
- 容器逐件记录物品实例、位置、方向和状态；T0不以数量字段代表多个单位。

### 10.2 未搜索状态

- 首次打开容器时，右侧格网不立即公开全部内容。
- 未确认区域显示扫描纹理、问号或“未知”。
- 未揭示物品不能查看名称、尺寸、价值或操作菜单。
- 容器空格从打开时直接显示；只有实际存在但尚未揭示的物品区域显示未知状态。

### 10.3 逐件揭示

1. 容器界面打开后自动开始搜索。
2. 搜索进度持续增长。
3. 内容按照容器格位从左上到右下逐件揭示。
4. 每次揭示一个完整物品卡及其占格形状，不逐格揭示同一物品。
5. 已揭示物品可以立即拖动或快速转移。
6. 容器中的空格从打开界面时就直接显示为空；只有实际存在但尚未揭示的物品显示未知状态。
7. 搜索进行期间允许玩家整理左侧背包，也允许立即取走已经揭示的物品。

开局木柜只有一根铁棍，因此第一次搜索应快速揭示铁棍，用来教学“未知→发现→转移”。具体时长等待程序原型测试。

### 10.4 搜索中断与保存

- 只有容器界面打开时搜索才推进。
- 玩家关闭界面、离开交互距离或界面被强制关闭时暂停搜索。
- 重新打开后从原有进度继续，不从零开始。
- 已揭示物品保持可见。
- 搜索进度、已揭示项目、已取走物品和容器开启状态写入存档。
- 玩家主动放入容器的物品立即可见，不需要重新搜索。

## 11. 容器转移规则

- 搜刮界面左侧背包、右侧容器均支持拖放。
- 双击容器物品时尝试自动放入背包。
- 双击背包物品时尝试自动放入当前容器。
- 双击和快速转移均允许自动旋转非正方形物品以寻找合法空间。
- 转移必须先验证目标连续空间，成功后再修改来源。
- 转移失败时物品保持原位，不允许先删除再尝试恢复。
- 容器关闭时，鼠标持有物返回来源。
- 玩家背包已满时可以先在背包内部重新排列，再尝试转移。

## 12. 视觉规范

沿用已选择的方案1方向：

- 石墨黑与枪灰色半透明面板。
- 低饱和橄榄色基础格。
- 米白色主要文字。
- 铁锈橙用于选择、关键按钮和工具状态。
- 冷青色用于搜索进度和技术反馈。
- 面板使用直角或极小圆角、细边框、克制磨损。
- 不使用枪械、弹药、军事阵营标识或其他与本项目无关的视觉语言。
- 不直接复制参考游戏的图标、字体、商标或具体版式素材。

## 13. 当前程序改造影响

现有程序使用固定槽位和IMGUI原型，需要进行结构升级：

- `InventoryModel`改为二维占用数据，保存坐标、方向和尺寸。
- `ItemDefinition`增加网格宽高、旋转和背包图标字段。
- `InventorySlot`不再代表“一格一件”，改为由容器保存物品实例及占用区域。
- `InventoryUI`改用UGUI或UI Toolkit实现拖放、旋转和跨格物品卡。
- `ContainerUI`固定为右侧面板，并支持未知、揭示中、已揭示和空状态。
- `WorldContainer`保存搜索进度和每件内容的揭示状态。
- `HotbarSystem`区分两个实际手位与四个背包引用位；手位保存物品实例，引用位只保存实例ID。
- `CraftingSystem`统一查询背包网格和左右手位，不能遗漏手持物，也不能重复统计`3`至`6`号引用位。

数据模型应先完成，再制作最终视觉界面，避免UI依赖旧的一维槽位结构。

## 14. T0暂不包含

- 物品重量和超重。
- 保险箱、安全箱或死亡保护格。
- 弹挂、弹药与枪械专用槽。
- 自动整理最优解算法；T0可以提供简单顺序整理。
- 容器搜索技能树。
- 搜索声音对敌人产生影响。
- 多人同时搜索同一容器。

## 15. 原型验收标准

- 1×2铁锤以一个连续物品卡正确占用两格。
- 1×3简易撬棍可以旋转并正确检测边界和碰撞。
- Tab界面默认只显示背包；点击背包右上角制作按钮后，制作窗口在右侧展开。
- 搜刮界面始终左背包、右容器。
- 12、20、30格背包升级后网格尺寸正确变化。
- 快捷栏固定6位；`1`、`2`号左右手位不占背包空间，`3`至`6`号引用位不提供额外存储空间。
- 快速转移只在存在合法连续空间时成功。
- 容器内容逐件揭示，重新打开后保留进度。
- 背包已满、物品冲突和搜索中断均不会导致物品丢失。
- 打开界面时玩家输入锁定，但世界继续运行。

## 16. 搜索中断规则

- 玩家主动按`Tab`或`Esc`时关闭界面并暂停搜索。
- 玩家离开交互距离时自动关闭界面并暂停搜索。
- 玩家受到伤害时自动关闭界面并暂停搜索。
- 玩家仅受到外力推动但仍在交互距离内时保持界面；超出距离后关闭。
- 容器被移动、禁用或销毁时立即关闭界面。
- 进入其他互斥界面时关闭容器界面。
- 饥饿或口渴跨越速度档位不会自动关闭界面。
