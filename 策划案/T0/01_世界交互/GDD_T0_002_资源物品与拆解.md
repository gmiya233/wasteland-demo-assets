# GDD_T0_002：都市资源、物品与拆解

版本：v0.2  
状态：审核中

## 1. 目标

T0资源来自现代都市中真实存在的物体。玩家不是寻找抽象的“废钢资源点”，而是观察环境、判断物体构成，并通过拾取、搜索、拆卸和破拆取得可用材料。

核心原则：

1. **物体就是资源来源**：汽车、货架、储物柜、家电和管道本身承载材料。
2. **所见基本可信**：可见部件与主要产出应有合理对应关系。
3. **先复用、后回炉**：完整零件通常比混合废料更有价值。
4. **工具改变方法**：不同工具开放不同部件和拆解方式，不只是提高数值。
5. **探索推动发展**：都市物资通常有限，玩家需要不断扩大搜索范围。
6. **适度抽象**：保留现实逻辑，但不要求逐颗螺丝进行拟真操作。

## 2. T0三类资源对象

T0使用三类能力描述资源。它们不是互斥的美术分类，同一个世界物体可以同时拥有多种能力。

### 2.1 可收纳资源

能够作为独立物品直接进入背包的小型资源，统一称为“可收纳资源”。出现位置不改变其类型：同一根短钢管既可以露天生成，也可以出现在储物柜内部。

示例：

- 弯曲钢筋
- 短钢管
- 松动金属板
- 螺栓和紧固件
- 废旧工具
- 断裂链条
- 布料、绳索和空容器

规则：

- 出现在世界表面时，使用短按交互直接拾取。
- 出现在资源容器内时，通过容器界面转移到背包。
- 不需要拆解工具。
- 必须具有合理的放置表面和环境语境。
- 拾取后直接尝试进入背包；背包已满时留在原地。
- 小型物品主要帮助开局和补充资源，产量不能替代大型物体拆解。

### 2.2 资源容器

能够保存可收纳资源的对象，统一称为“资源容器”。玩家打开或搜索容器，再将内部物品转移到背包。

容器示例：

- 工具箱
- 金属储物柜
- 抽屉
- 汽车后备箱
- 垃圾箱
- 维修柜
- 仓库货箱
- 废弃机器维护仓

可能内容：

- 工具
- 食物和饮水
- 铜线
- 紧固件
- 机械零件
- 少量含铁废料
- 柴油等稀有探索物资

规则：

- 容器内容与容器本体是两个独立资源层。
- 内容来自`LootProfile`，容器本体来自`SalvageProfile`。
- 关键进程物品使用固定或保底配置，不完全依赖随机概率。
- 容器内容首次生成后写入存档，反复开关不得重新抽取。

### 2.3 大型资源

无法直接放入背包、必须留在现场使用工具拆解的物体，统一称为“大型资源”。汽车、金属储物柜、家电和工业设备都属于大型资源。

大型资源规则：

- 至少需要一种合适工具才能开始拆解。
- 通过一个或多个拆解阶段产出可收纳资源。
- 拆解阶段可以改变外观、开放新部件或留下不可处理的主体。
- 拆解状态永久保存，不会因区域重新加载而复原。

资源容器与大型资源可以叠加。容器在被搜索后，仍可以作为大型资源拆解其本体。

以金属储物柜为例：

```text
金属储物柜
├── 内部：工具、铜线、紧固件等
└── 本体：薄钢板废料、铰链、基础紧固件
```

规则：

- 容器未清空时允许拆解，但必须明确提示。
- 拆解后，内部剩余物品掉落在原位置附近，不得被销毁。
- 玩家建造的储物设施不使用废墟物体的默认拆解逻辑。
- 任务关键容器可以禁止拆解，或在条件完成后再允许拆解。
- 容器本体拆解通常需要撬棍、锤或扳手。

### 2.4 组合与分阶段拆解

金属储物柜同时是资源容器和大型资源；汽车、机床、空调机组和大型家电也可以同时保存可收纳资源并支持现场分阶段拆解。

规则：

- 大型物体由多个可拆部件或拆解阶段组成。
- 每个阶段可以拥有独立工具要求、耗时、产物和视觉状态。
- 已缺失的部件不会重复产出。
- 玩家可以只取高价值部件后离开，也可以继续拆解主体。
- 拆解进度和剩余部件必须进入存档。
- 主体耗尽后保留空壳、基础残件或清理后的状态，不要求凭空消失。

## 3. 都市含铁资源来源

现代都市中的主要铁类来源实际以钢材为主。游戏使用“含铁资源”作为大类，再区分废料形态与可复用部件。

### 3.1 街道与停车区域

- 废弃汽车和摩托车
- 自行车
- 道路护栏
- 路牌和支架
- 排水格栅与井盖
- 金属垃圾桶
- 施工围挡
- 购物车和手推车
- 路灯杆

### 3.2 住宅区域

- 铁床架
- 金属门与防盗窗
- 暖气片和热水器
- 燃气灶
- 冰箱、洗衣机等家电外壳
- 金属橱柜
- 水管和阀门
- 家用工具箱

### 3.3 商业区域

- 超市货架
- 购物车
- 卷帘门
- 金属柜台
- 空调外机
- 自动售货机
- 储物柜
- 办公家具金属框架
- 电梯和维护设备

### 3.4 工业与施工区域

- 钢梁、钢板和钢筋
- 脚手架
- 工业管道与阀门
- 机床和电机
- 油桶
- 发电设备
- 机械外壳
- 工程车辆

区域差异体现为物体类型与材料构成不同，而不是简单提高“资源点产量”。

## 4. 含铁回收物分类

T0不应让所有金属物体只产出同一种“废钢”。建议逐步迁移到以下分类：

| 分类 | 定义 | 典型来源 | T0用途 |
|---|---|---|---|
| 含铁废料 | 混合、锈蚀或形状不规则的铁质材料 | 破损柜体、杂乱残片 | 工作台分选 |
| 薄钢板废料 | 可手工整形的薄板 | 家电外壳、汽车面板、铁柜 | 地基部件、设备外壳 |
| 钢制零件 | 仍具有结构或机械价值 | 支架、轴、铰链、链条 | 直接复用或加工 |
| 基础紧固件 | 螺栓、螺母、螺钉等 | 工具箱、家具、设备连接处 | 建造和装配 |
| 铸铁废件 | 厚重且不易手工加工 | 发动机、暖气片、机床底座 | 后续加工预留 |
| 可用钢料 | 经分选和基础处理的标准输入 | 含铁废料加工 | 手工制板与零件 |
| 金属板 | 可用于建造和制造的加工材料 | 薄钢板整形或钢料加工 | 锅炉、发电机、建筑 |

现有数据表保留`scrap_steel`技术ID，并将其中文显示名称迁移为“含铁废料”。存档和配方继续引用原ID。

## 5. 工具与拆解方法

| 工具/方式 | 主要行为 | 适合对象 |
|---|---|---|
| 徒手 | 拾取、翻找、取下松动物品 | 表面散落物、开放容器 |
| 撬棍 | 撬开、分离面板、打开卡死结构 | 柜门、车门、薄板外壳 |
| 锤类工具 | 破拆、整形、敲除连接 | 锈死外壳、砖石附着件、薄板 |
| 扳手 | 拆卸螺栓连接和机械组件 | 车轮、管件、阀门、电机附件 |
| 后续切割工具 | 切割厚钢和主体结构 | 车架、钢梁、大型设备 |

规则：

- 工具要求使用能力标签，例如`Tool.Pry.T1`，不判断具体物品ID。
- 工具耐久只在拆解阶段成功结算时消耗。
- 工具可以影响可访问部件、耗时、产物完整度或回收率。
- T0优先表现“能拆什么”的差异，具体效率数值待程序原型完成后测试。

## 6. 大型物体案例：废弃汽车

汽车在T0需要支持完整拆解，但开发优先级低于金属储物柜、可收纳资源、背包和基础工具系统。

```text
废弃汽车
├── 驾驶舱与后备箱：食物、工具、杂物
├── 蓄电池：电气部件与后续材料
├── 线束：回收铜线
├── 车轮：橡胶与钢制零件
├── 外壳：薄钢板废料
├── 发动机：机械零件与铸铁废件
└── 车架：大量含铁废料，需要后续切割能力
```

设计要求：

- 车辆生成时可以随机缺失部分部件。
- 搜索内部和拆解车体是独立行为。
- 拆解部件后更新可见模型或隐藏对应部件。
- 玩家在T0可能无法完全处理车架，从而形成未来回访目标。
- 柴油、工具和关键零件属于探索奖励，不保证每辆车都有。

“完整拆解”指汽车定义的所有T0阶段均可执行；阶段可以要求T0后期工具，不代表玩家首次发现车辆时就能全部拆完。

## 7. 首个程序原型对象

第一个交互对象改为“金属储物柜”，不再使用抽象的“废钢残骸”。

测试场景建议包含：

- 一只金属储物柜
- 柜内的回收铜线与基础紧固件
- 柜旁表面的弯曲钢筋、短钢管和松动金属板
- 一把用于测试的撬棍

原型流程：

1. 玩家直接拾取表面散落物。
2. 玩家打开储物柜并查看内部物品。
3. 玩家取出部分或全部内容。
4. 玩家装备撬棍并拆解柜体。
5. 未取出的内部物品掉落到地面。
6. 柜体产出薄钢板废料、铰链或紧固件。
7. 柜体切换为已拆状态。

该对象同时验证拾取、容器、库存、工具条件、拆解、掉落保护和视觉状态。

## 8. 世界生成与刷新

### 可收纳资源生成点

- 使用生成点布置，不要求关卡设计师逐个摆放最终物品。
- 生成点由关卡设计师放置，并配置环境语境、允许物品、数量范围和是否固定产出。
- 通过“可收纳资源类型 + 合理表面标签”控制位置。
- 例如紧固件出现在维修台附近，钢管出现在施工区或设备间。
- 拾取后通常不自然刷新。

### 容器内容

- 首次生成或首次打开时确定，并立即写入存档。
- 清空后不自动补货。
- 特殊世界事件可以创建新容器或补给，但不属于T0基础规则。

### 可拆世界物体

- 拆解状态永久保存。
- 不定时复原，不在玩家离开后重新生成材料。
- 自然资源可以单独设计再生规则，不与都市废墟物体共用刷新逻辑。

这种有限性用于推动玩家从住宅区逐步探索商业区、维修区和工业区。

## 9. 稀缺性与区域结构

- 含铁废料：城市中广泛存在，但受工具、背包格数和运输距离限制。
- 薄钢板废料：家电、车辆和金属家具区域较多。
- 紧固件：小型但重要，工具箱和机械连接处稳定产出。
- 铜线：电器、车辆线束和维护柜中获得。
- 机械零件：汽车、机床、空调和泵类设备中获得。
- 柴油：车辆、维修区或储存设施中的稀有战利品，T0不可制造。
- 关键进程材料必须存在确定性来源，随机产出只能作为额外奖励。

资源的主要门槛依次是：发现位置、拥有工具、背包格数、拆解耗时和运输距离。

## 10. 程序数据模型

不再以单一`ResourceNode`代表所有资源来源。建议使用通用世界对象加可组合能力：

```text
WorldSalvageObject
├── SurfaceLootComponent
├── SearchableComponent
├── ContainerComponent
├── DismantleComponent
├── SalvageStageComponent
└── VisualStateComponent
```

### 基础定义

- `WorldObjectDefinition`：世界物体名称、ID、模型和基础标签。
- `LootProfile`：表面或容器内部的物品配置。
- `SalvageProfile`：拆解工具、耗时、产物和耐久消耗。
- `SalvageStageDefinition`：大型物体的单个拆解阶段。
- `VisualStateDefinition`：完整、打开、缺失部件、已拆空等表现。

### 组合示例

```text
金属储物柜
├── ContainerComponent → LootProfile_Locker_Maintenance
├── DismantleComponent → SalvageProfile_MetalLocker
└── VisualStateComponent → Closed / Open / Dismantled
```

```text
废弃汽车
├── SearchableComponent → 驾驶舱与后备箱
├── SalvageStageComponent → 电池、线束、车轮、外壳、发动机、车架
└── VisualStateComponent → 各部件存在与缺失状态
```

玩家交互系统只查询对象当前提供的动作，不判断目标是汽车、储物柜还是家电。

## 11. 物品通用规则

- 所有物品具有稳定且不可复用的`ItemId`。
- 世界物体实例具有独立且可保存的`WorldObjectInstanceId`。
- 一个物品可以拥有多个分类和用途标签。
- 世界拾取物、背包物品和配方输入引用同一个`ItemDefinition`。
- 完整部件、混合废料和加工材料使用不同物品定义。
- 工具和可修复物品使用通用耐久框架。
- 重量、品质、纯度和温度字段保留扩展位，T0暂不参与计算。

## 12. 防卡死规则

- 起始区固定放置足够的表面散落物，使玩家能制作第一件工具。
- 第一把关键工具所需材料不依赖上锁容器或该工具自身。
- 损坏或丢失工具后，玩家仍能通过低效率路线重新制造。
- 背包已满时，拾取物和拆解产物不得消失。
- 拆解未清空容器时，内部物品必须安全落地。
- T0最终所需的铜线、机械零件和损坏旧电灯具有确定性探索位置。
- 稀有战利品只能加速进度，不能成为唯一通关条件。

## 13. 数据迁移事项

现有数据表仍使用以下旧概念：

- `scrap_steel`：暂时对应“含铁废料”。
- `mechanical_scrap`：需要进一步区分完整机械零件与混合机械碎件。
- 部分配方直接将废钢分选为钢料，产出比例仍是占位值。

在开始实现`ItemDefinition`前需要完成：

1. 保留`scrap_steel`技术ID，将中文显示名称改为“含铁废料”。
2. 增加薄钢板废料、钢制零件、铸铁废件和必要的小型可收纳资源。
3. 为金属储物柜建立第一份`LootProfile`和`SalvageProfile`。
4. 为露天可收纳资源建立语境化生成点配置。
5. 将交互原型中的“废钢残骸”替换为金属储物柜与可收纳资源。
