# GDD_T0_003：交互与采集

版本：v0.1  
状态：待审核

## 1. 目标

用统一交互框架支持拾取、搜索、拆解、容器和机器，确保未来增加维修、开锁或连接行为时无需改写玩家控制器。

## 2. 基本操作

- 玩家视野中心或近距离检测可交互目标。
- 当前目标高亮并显示动作、按键、条件和预计结果。
- `E`短按执行即时动作；`E`按住执行耗时动作。
- 同一物体有多个动作时，通过简洁的动作切换选择，T0避免复杂径向菜单。
- 移动过远、跳跃、切换工具或目标失效会中断持续交互。

## 3. T0交互类型

| 动作 | 形式 | 示例 |
|---|---|---|
| 拾取 | 即时 | 地面物品进入背包 |
| 搜索 | 持续 | 搜索柜子并显示内容 |
| 拆解 | 持续/重复 | 使用撬棍拆废钢残骸 |
| 采集 | 持续 | 获取木材或纤维 |
| 打开 | 即时 | 打开储物箱界面 |
| 操作 | 即时 | 打开机器或锅炉界面 |
| 建造 | 模式化 | 放置设施预览并确认 |

## 4. 统一交互契约

每次交互由以下信息组成：

- 交互者：谁发起行为。
- 目标：哪个对象接收行为。
- 动作：拾取、搜索、拆解等。
- 条件：距离、工具、背包空间、权限、目标状态。
- 过程：即时、持续时间、能否中断。
- 结果：物品、状态变化、事件和反馈。

玩家控制器只负责选择目标和提交请求，不负责生成奖励或修改机器库存。

## 5. 反馈规则

- 可执行：显示动作名称和按键。
- 缺少条件：仍显示目标，并明确提示缺少的工具或空间。
- 持续交互：显示进度；中断后T0默认清空本次进度。
- 成功：音效、动画、简短物品获得信息。
- 失败：说明具体原因，禁止只显示“无法交互”。
- 多个目标重叠时，优先屏幕中心、距离更近且可执行的目标。
- 工具耐久只在交互成功结算时扣除；低耐久预警不得阻止玩家完成当前动作。
- 工具耐久归零后动作不可执行，并提示维修或替换方式。

## 6. 首个对象：废钢残骸

基础流程：

1. 玩家靠近后看到“按住E：翻找废钢残骸”。
2. 徒手可获得少量松散废钢。
3. 装备撬棍后显示更高效的“拆解”动作。
4. 完成后由掉落配置生成物品并尝试进入背包。
5. 背包不足时，多余产物生成在目标附近，禁止静默丢失。
6. 残骸耗尽后改变外观并停止提供资源。

## 7. 技术边界

- 目标通过可交互接口暴露动作列表。
- 条件和结果尽量使用可组合数据，而非对象类型判断。
- 动画、音效、UI订阅交互事件，不反向控制核心结果。
- 交互层不得直接依赖具体背包实现，通过库存接口提交物品。

## 8. 待讨论

1. 交互目标采用角色朝向、摄像机准星，还是二者混合判定？
2. 持续交互被中断后是否保留部分进度？
3. 拆解产物自动进入背包，还是先以实体形式落地？
